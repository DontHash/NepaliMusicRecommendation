## 2. What is already strong (with evidence)

- **Transliterator has a real layered system and an honest eval harness.** Generated lexicon + context bigrams + char model with switchable A/B layers (`transliterator.py:459-502,567-569`), a nonzero-exit regression gate (`check_transliteration.py:263-273,310-321`), per-difficulty slices and worst-error lists (`transliteration_report.json:26-183`), and a forgetting guard on Aksharantar test (`check_transliteration.py:200-236`). Gold lines were verified to have **zero overlap** with the 34k teacher-labeled training lines (checked) — no teacher leakage.
- **Documented negative result.** The muRIL tweet student collapse is written up and the distillation kernel kept (`music_rec/KAGGLE.md:57-64`; `kaggle_jobs/sentiment_distill.py:348-362` records `prob_std`≈0.001, `collapsed: 1`).
- **ONNX path engineered with a parity gate before adoption.** `check_onnx_parity.py:25` (min cosine 0.9999), CPU provider pinned (`onnx_encoder.py:32-34`), fallback to torch (`embeddings.py:104-125`), background warmup and lexical-first degradation (`web_app/server.py:36-45,177-202`).
- **Thread-safe shared model singleton** with double-checked locking (`embeddings.py:58-75`), CPU pinning for the web app (`server.py:22`; `PROJECT_GUIDE.md:805-823`), and documented latency: ONNX ~2.4 s load / ~0.02 s per query vs torch ~14 s / ~0.2 s (`PROJECT_GUIDE.md:811-817`).
- **Kaggle install validates artifact/corpus alignment**: row count, `song_id` order, finiteness, window-owner bounds (`kaggle_embeddings.py:187-206`).
- **Line-level calibration is evaluated leave-one-song-out**, not in-sample only (`check_line_attribution.py:253-277`; LOOCV 0.506 vs in-sample 0.510 in `line_attribution_tuning.json:2070-2080`).

## 4. Top 10 improvements (ranked by impact / effort)

1. **Artifact manifest + startup preflight (S–M).** Write `artifacts/manifest.json` (path, sha256, mtime, rows, dims, model id, corpus hash, window params) at build time in `embeddings.py`/`kaggle_embeddings.py`, `train_mood_probe.py`, `finetune_transliterator.py`. On startup (`web_app/server.py`, `recommender.py`) verify dims/rows/hash and either fail fast or degrade with a logged reason. Gain: kills the entire silent-drift class. Deps: none.
2. **Make the probe reproducible (S).** Change default `--pseudo` to `R_data/raw/gemini/corpus_v3/labels_merged.csv`; save a sidecar `mood_probe_meta.json` (label file sha, teacher model ids, embedding sha, seed, thresholds, git commit, metrics) and load it in `mood_attribution.py:147-158`. Re-run once to confirm `mood_probe_report.json` matches. Gain: auditability/rollback.
3. **Fix mood metrics and report base rates + CIs (S).** In `mood_gold_eval.py`, report exact-match, multi-label micro/macro F1, per-class P/R with bootstrap 95% CIs, and always-negative/always-both baselines; stratify by `source` and `confidence`. Gain: honest numbers; catches metric gaming.
4. **Calibrate probabilities properly and persist calibration (M).** Temperature/isotonic or per-label Platt on cross-validated folds; store `temperature`/`calibrator` in the probe artifact; report ECE/reliability. Replace the hardcoded `LINE_BIAS` (`mood_attribution.py:30-31`) with params loaded from the artifact. Reference: Guo et al., ICML 2017. Gain: UI probabilities become meaningful.
5. **Wire existing eval gates into CI + per-slice thresholds (M).** GitHub Actions: unit tests, `check_transliteration.py` (long-line and NE slices), `check_probe_parity.py`, `check_onnx_parity.py`, mood gold/line gold evals, with a versioned artifact cache. Gain: regressions caught pre-merge; removes reliance on manual runs.
6. **In-domain contrastive fine-tune of mpnet with hard negatives (L).** Build (query-line, song) positives from the query set + teacher paraphrases; mine hard negatives from current top-k (false positives); train with MNRL/SimCSE-style loss; re-embed and re-run nDCG plus a small human judgment pool. References: SimCSE, GPL, arXiv 2509.09459. Gain: the largest single retrieval-quality lever.
7. **Retire or properly train fear/depression; threshold-tune anger (S–M).** Either drop the two labels from artifacts/UI or collect ≥300 labels each with class-weighted training; tune anger threshold on a held-out split to trade precision for recall; add macro F1 excluding unsupported classes. Gain: removes misleading outputs.
8. **Model cards + registry aliases (M).** One markdown card per model (data, teacher/prompt, metrics + slices, intended use, limits), plus MLflow (or DVC + git tags) with `@champion`; reports record the artifact digest. Gain: lineage, rollback, onboarding.
9. **Drift monitoring + retraining triggers (M–L).** Log per-request signals (transliteration OOV/fallback rate, empty-result rate, score percentiles, query language mix); compute PSI/KS versus training-time distributions; schedule re-labeling + probe retrain on threshold breach; shadow-evaluate the candidate on gold before promotion. Gain: quality stays measurable over time.
10. **Serving hardening for the model path (M).** Lock the lazy loaders or preload attributor/neighbors in warmup; bound `_payload_cache`; add request latency histograms and a readiness endpoint that distinguishes liveness/model readiness; log a warning when the transliterator or ONNX artifact is unavailable. Deps: #1. Gain: predictable cold start and operability.

## 5. Verdict

The ML core is **POC-quality engineering with a solid evaluation instinct**, not a scalable model lifecycle. Two of three model families (transliterator, mood probe) have genuine, switchable, measured pipelines and honest negative results; the embedding family is deliberately off-the-shelf. What is missing is not algorithms-as-such but the *contract around them*: no registry/cards/hashes, a probe that cannot be retrained from defaults, reports that disagree with each other, gold sets too small for point estimates, and software gates (ONNX, translit, probe) that exist as scripts rather than CI/startup checks. This is fixable with mostly small engineering, and the model architecture itself would survive scale — but today a single stale artifact can corrupt every recommendation without any signal. Treat it as `LACKS-SCALE` for data/labels + `PROD-GAP` for lifecycle; the algorithm stack is directionally right. Highest-leverage algorithmic change: contrastive in-domain fine-tuning of the embedding with hard negatives.
