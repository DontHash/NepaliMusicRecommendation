## 2. What is already strong (with evidence)

- **Deliberate cold-start strategy.** ONNX query encoder with a measured parity gate (~2.4 s load / 0.02 s query vs ~14 s / 0.2 s torch) plus background warmup and a lexical-only degraded path (`PROJECT_GUIDE.md:811-823`; `embeddings.py:95-133`; `server.py:36-52,189-199`).
- **Genuinely thread-safe shared model cache**: double-checked locking for mpnet and ONNX sessions (`embeddings.py:58-75,117-122`) with real concurrency tests (`tests/test_shared_model.py:51-71`).
- **Documented hardware-contention diagnosis**: GPU + WebGL `CONTEXT_LOST`; app pins CPU via env (`server.py:22`, `run_web_app.py:20`, `embeddings.py:28-41`, `PROJECT_GUIDE.md:805-810`).
- **Explicit failure-state UX**: search failure/empty/warming notes in the dropdown (`app.js:562-580`), C13 change record (`git log 2791246`).
- **Locks on recommender's lazy BM25/dedup** (`recommender.py:73-75,88-108,111-116`) and honest backend-failure search test (`tests/test_web_app.py:101-106`).
- **Small, self-contained static app**: no build step, vendored three.js r180 (`three.core.js:6`), one CDN-free deployable directory.
- **No SSRF surface**: the serving process never fetches user-supplied URLs; all HTTP fetching lives in offline `data_collection/`/labeling scripts. No `requests/httpx/urllib` imports in `music_rec/` or `web_app/`.
- `.env` is gitignored and contains only Gemini API keys used by offline labeling scripts (`scripts/api_label.py:94-101`), not by the server.

## 4. Top 10 improvements (ranked by impact / effort)

1. **Escape all DOM injection (S).** Replace `innerHTML` title/artist interpolation in `renderNeighbors`/`runSearch` with `textContent`/`createElement`; add a CSP header. Effort S; gain: removes stored-XSS in a scraped-data product. Deps: none.
2. **Bound and validate inputs + add timeouts (S).** `AnalyzeRequest.text` `max_length` (~20k chars), `q` max, clamp `search.limit` to `[1,50]`, reject negatives; document/return 413/422; add a per-request inference deadline using a semaphore around `_lyric_hits`/`attribute_text`. Effort S; gain: prevents trivial self-DoS. Deps: none.
3. **Lock server lazy singletons and make warmup observable/retryable (S).** Give `_corpus`, `_recommender`, `_translit_helper`, `get_attributor`, `get_mood_neighbors` double-checked locks; record warmup failure state; reset `_loading` on failure with bounded retry. Effort S; gain: no duplicate 12–182 MB loads, no permanent silent degradation. Deps: none.
4. **Health/readiness/version split (S).** Add `/healthz` (process), `/readyz` (encoder + recommender + probe + windows + recommender.lexical loaded), `/version` (app + commit + artifact hashes); make `/api/status` return a structured detail object. Effort S; gain: deployable behind probes; alertable. Deps: #3.
5. **Pin the environment (S/M).** Add `pyproject.toml` with `requires-python>=3.10`, a lockfile (uv/pip-tools) with hashes for the serving subset, pin HF model `revision=` in `config.py`, pin FastAPI/uvicorn explicitly. Effort S–M; gain: reproducible builds; prevents torch/transformers drift. Deps: none.
6. **CI with an artifact strategy (M).** GitHub Actions: lint/type + unit tests on every PR; artifact-dependent Studio tests on a job that restores a versioned artifact bundle (see #7), plus a scheduled ONNX parity run. Effort M; gain: regressions caught before merge; honest test signal. Deps: #7, #5.
7. **Artifact registry + manifest + fetch script (M).** Publish `embedding_onnx`, `window_vectors/owners`, `mood_probe.npz`, `embeddings.npy`, `lyrics.faiss` as versioned release assets (GitHub Releases/S3/MLflow) with SHA-256 manifest; add `scripts/fetch_artifacts.py --verify`. Effort M; gain: any machine can serve; evals become reproducible. Deps: none.
8. **Observability baseline (M).** Structured JSON logging with request IDs, Prometheus counters/histograms (search latency, analyze latency, warmup failures, payload cache size, RSS), OpenTelemetry traces, Sentry/error aggregation. Effort M; gain: SLOs and incident detection. Deps: #3, #4.
9. **Perimeter security (M).** API-key/session auth, per-key rate limits (token bucket at gateway or SlowAPI), explicit CORS allow-list, TLS termination, and default-bind documentation; move `.env` keys to a secrets manager with rotation. Effort M; gain: safe public exposure. Deps: deployment (#10).
10. **Production serving topology + payload efficiency (M/L).** Container with gunicorn/uvicorn workers (or ≥2 replicas behind a load balancer), `GZipMiddleware`, static asset hashing/minification and long-cache + ETag revalidation; optionally Redis for `_payload_cache` and search hot cache. Effort M–L; gain: concurrency, bandwidth, memory bounds. Deps: #5, #7.

## 5. Verdict

This track lacks **production engineering**, and the serving architecture also lacks **scalability** as written. What exists is a well-instrumented single-user POC: thoughtful cold-start handling (ONNX export with parity gate, shared model singleton, lexical fallback, documented GPU/WebGL contention), honest degradation UX, and zero unsafe server-side fetching. But the process is a single uvicorn instance (`run_web_app.py:36`), all inference is unbounded and uncontrolled on the event loop's threadpool, lazy singletons race on cold start, request bodies have no limits, there is no auth/rate limiting/compression, no CI/containers/artifact pipeline, and the only health signal is a boolean that never distinguishes liveness from readiness. A new machine cannot even reproduce the 1.27 GB artifact set without manual Kaggle steps, and dependency/model versions are unpinned. At 10× users the first CPU-heavy paste or a cold-start stampede degrades the service; at 100× it will not function without the changes in §4. The good news is that most fixes are small–medium and do not require re-architecting the ML core.

## 6. Open questions / uncertainty

- Actual steady-state RSS was not measured (read-only audit): estimates (~2.5–3 GB with ONNX session + shared torch mpnet + 182 MB windows + BM25) are inferred from artifact sizes, not sampled.
- `.env` values were not inspected; key validity/scope unknown, and whether any deployment has ever run with `--host 0.0.0.0` is unverifiable from the repo.
- No CI history exists, so "tests pass" cannot be independently confirmed in a clean environment; Studio tests skip when windows are absent.
- Uvicorn/FastAPI/torch versions in the author's environment are unknown (unpinned), so some behaviors (threadpool size, anyio limits, ONNX arena behavior) may differ on other machines.
- Whether the project intends public deployment (vs. localhost demo) is unclear; P1 security ratings assume a shared or public deployment — if it remains 127.0.0.1-only, auth/rate limiting drop to P3.
- `_payload_cache` worst-case size depends on real lyric lengths; not measured across all 4,157 songs.
