## 2. What is already strong (with evidence)

- **Resumable work store done right for its size**: SQLite WAL + busy timeout (`state.py:76-83`); `INSERT OR IGNORE` dedupe by stable `dedupe_key` (`state.py:104-132`); upsert lyrics by `candidate_id` (`state.py:203-227`); status machine + attempt counters + `attempts` audit table (`state.py:12-73`, `159-200`). Schema includes indexes on status/sha (`state.py:70-72`).
- **Cache-first HTTP with real hygiene**: content-addressed cache (`http.py:67-89`), atomic writes, exponential backoff with jitter, `Retry-After` respect, 404 short-circuit, per-host rate limits and an in-process circuit breaker (`http.py:114-194`, `config.py:12-33`).
- **Good input provenance for bootstrap corpora**: each import report records input path + SHA-256 (`bootstrap.py:36-41,135-156`).
- **Compaction snapshots are hashed and retained**: atomic CSV write, timestamped snapshot, sidecar `.sha256`, 5-deep retention (`compact.py:98-135`).
- **Post-hoc quality work is unusually thorough for a POC**: a real artifact audit with cross-song template mining (`audit_corpus_quality.py:180-192`), a curated 140-line blacklist generated from it (`template_blacklist.py:1-13`), a rebuild that cut 4,218 artifact lines across 903 songs to 11 lines across 10 songs while preserving `song_id`s (`corpus_quality_report_v2.json`; `rebuild_corpus.py:151-208`), quarantine records (`corpus_quarantine.csv`, 3 rows), stale-gold isolation (`eval/gold_exclusions.csv`), and a reviewed typo map (`music_rec/typo_map.py:1-12`; `eval/corpus_typo_map.csv`).
- **Gold discipline in annotation**: gold songs excluded from corpus labeling (`api_label.py:273-280`), few-shot examples withheld from metrics (`api_label.py:36,125-139`), schema-constrained JSON with per-item validation (`api_label.py:70-91,169-182`), append-only JSONL resume (`api_label.py:305-314,333-358`), and a teacher-vs-human gate (relaxed acc 0.911, `PROJECT_GUIDE.md:705`).
- **Transliteration quality gates actually block regressions** (`PROJECT_GUIDE.md:189-193`), unlike the rest of the data path.

## 4. Top 10 improvements (ranked by impact / effort)

1. **Wrap the pipeline in an orchestrator as data assets (Dagster or Prefect; Airflow if ops-managed).** Define `enumerate → crawl/harvest → fetch → prune → compact → audit → rebuild → embed → label → index` with per-asset idempotency, retries, backfills, and run history. Effort **M**. Gain: removes manual sequencing (gaps 1, 6, 15). Depends on: queue claim (item 2).
2. **Make the work queue concurrency-safe and complete.** Transactional claim (`UPDATE candidates SET status='fetching' WHERE id IN (SELECT … LIMIT n)` / `RETURNING`), lease TTL + `reset_orphaned` at startup, explicit `failed`/`dead` status, page attempt counters. Effort **M**. Gain: gaps 2, 3, 4, 6; unlocks parallel fetch.
3. **Add a data-contract + expectation suite (`corpus_expectations.yml`) gating each rebuild in CI.** Assert row-count deltas, exact-dup rate, artifact-line ratio/budget, script mix, token/char distributions, quarantine rate, gold-set drift; fail the build on breach. Effort **M**. Gain: gap 9; converts ad-hoc audit into a monitor.
4. **Build canonical identity (music-entity service): MBID/ISRC-keyed songs/artists, normalized title/artist, version-aware matching, and MinHash/LSH near-dup candidates with a human review queue.** Use the already-declared `datasketch`. Export ISRC/IDs through compaction. Effort **L**. Gain: gap 8 and duplicate result rows; prerequisite for catalogue growth.
5. **Record full label provenance and freeze teacher versions.** Add `model, prompt_sha, key_alias, shard, ts, raw_response` to each JSONL row; one teacher version per label set; keep per-run usage/cost aggregates; re-run the gold gate before promotion. Effort **S–M**. Gain: gap 11; auditable, reproducible labels.
6. **Version the corpus and artifacts as a lakehouse-style table set.** Write Parquet/Delta/Iceberg with `source`, `fetched_at`, `corpus_version`, `code_git_sha`, `input_sha256`; back up `work.sqlite` or migrate to Postgres; keep manifests that chain raw → clean → labels → embeddings. Effort **M**. Gain: gaps 10, 12, 13.
7. **Implement a documented rights/takedown policy and stop redistributing lyrics.** Remove corpora from git and the Kaggle dataset, add LICENSE/NOTICE + attribution, run robots compliance checks per domain, and evaluate a licensed lyrics API (LyricFind/Musixmatch) for the product path. Effort **M–L** (legal). Gain: gap 14 (P0).
8. **Fix ingestion policy: best-version merge instead of first-write-wins; replace the romanized heuristic with a language-ID model; enable `syncedlyrics` fallback and per-source rejection dashboards.** Effort **S–M**. Gain: gaps 5, 7.
9. **Add structured logging + metrics + alerting** (fetch hit/miss/reject by source/stage, queue backlog age, circuit openings, quota errors) and persist circuit-breaker/cache state with TTL + conditional revalidation. Effort **S–M**. Gain: gap 15; makes 100x operably.
10. **Instrument and prune the candidate supply chain:** storefront-appropriate enumeration (`country=NP`), track yield per source/target, and retire low-yield sources; schedule fetch in fan-out workers. Effort **S–M**. Gain: gap 16; converts 27k stranded candidates into corpus.

## 5. Verdict

This area has **both** a scale and a scalability problem. The core is genuinely well built for one operator on one machine — WAL queue, hashed snapshots, honest retries, curated cleaner, and a quality rebuild that most POCs never do — but the engineering around it is POC-shaped: no orchestrator, no concurrency-safe claiming, no dead-letter path, no data contracts, no label provenance, no monitoring, and identity limited to string folding. At 10x (40k songs) the manual CLI steps, the 27k candidate backlog, and duplicate/identity drift become the day-to-day problem; at 100x (100k–500k songs) the missing contracts, lineage, and licensed-data path are blockers before compute ever is. The good news: the fixes are standard, incremental, and mostly S–M effort — this is a plumbing gap, not an architectural dead end.

## 6. Open questions / uncertainty

- **Cleaner recall is unmeasured.** The 11 residual artifact lines come from one regex audit; English blog prose, chord charts (`सी#एम`), and unknown site templates are outside its patterns (`PROJECT_GUIDE.md:843-846`). No human sample estimate exists, so "how noisy is the corpus?" cannot be answered precisely.
- **Pipeline timing is undocumented.** `R_data/corpus/rebuild.log` has no duration; my 12-row probe (76 songs/s) almost certainly hit lexicon/table fast paths and is not a valid 100k projection. Labeling cost can only be bounded from partial, overwritten reports.
- **Live DB state may be mid-experiment** (1 `fetching`, 247 `missed`), and its `harvested_artists` table is empty while an offline report claims 586 artists were harvested with 0 records each — evidence of state loss between runs, so status numbers are snapshot-in-time.
- **Legality is jurisdiction-dependent** and I am not a lawyer; the Kaggle dataset privacy state and each site's robots/ToS were not verified live.
- **`datasketch`, `lyricsgenius`, `pylast`, and `scrapling`/`browser.py` are declared/implemented but unused** — some "planned" capabilities may exist unmerged elsewhere.
